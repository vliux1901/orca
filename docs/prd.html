Summary

Build an Android app that helps users organize car maintenance documents, extract key facts, show a maintenance timeline, and answer simple factual questions with citations.

V1 should use cloud vision AI as the primary extraction path. We are not doing local OCR first because it loses structural information too early and performs poorly on real document photos and complex layouts.

Later, the app may add a local-model privacy mode for users who do not want cloud AI processing.

Target User

Private vehicle owners who want a reliable maintenance history for one or more cars.

Core user needs

  • Keep maintenance records in one place.
  • Understand maintenance and repair history.
  • Get answers backed by source documents.
  • See when extracted data is uncertain.
  • Have a future privacy-mode option.

Product Goals

  • Let users create vehicle profiles.
  • Let users import maintenance PDFs and photos.
  • Extract useful facts with source links.
  • Require users to provide their own OpenAI API key from an in-app Settings screen rather than bundling any API secret into the APK, and gate key decryption behind device credentials or biometrics when Orca needs to use or display the stored key.
  • Preserve document structure well enough to recover tables, totals, grouped service items, and similar layout-dependent content.
  • Show a chronological maintenance timeline.
  • Answer factual questions with citations and uncertainty.

V1 Scope

Supported document types

  • Service invoices
  • Repair orders
  • Maintenance receipts
  • Inspection reports related to maintenance or repair

Supported capabilities

  • Multiple vehicle profiles
  • Manual import of PDFs and photos
  • Extraction of key maintenance facts
  • Maintenance timeline
  • Search and simple factual questions with citations
  • User correction of extracted fields

Out of scope for V1

  • Non-maintenance vehicle documents
  • Email or cloud-drive import
  • Automatic background sync
  • Camera capture
  • Local on-device model execution
  • Mechanic-style recommendations or unsupported advice

Processing Direction

V1 document processing

  • Send imported document images or PDF pages directly to a cloud vision-capable AI model.
  • Do not rely on local OCR-first extraction as the default path.
  • Link extracted facts back to the source document and page.
  • Mark extracted results as unverified until the user confirms or corrects them.

Future privacy mode

  • Allow the user to choose a local model instead of a cloud model when local quality and device support are good enough.

Current Product Decisions

  • Platform: Android first
  • Import: file upload only
  • Multiple vehicles: yes
  • Source document storage: local in the app
  • Extraction path in V1: cloud vision AI first
  • Local models: later, as privacy mode

MVP Requirements

Vehicle Profiles

Required: display name, make, model, and year.

Optional: license plate, VIN, vehicle color, and a gallery-selected vehicle photo. Current mileage is not part of the create-vehicle flow.

Vehicle detail should use a stable top app bar title of Vehicle details. The profile card should emphasize the vehicle fields and show a large vehicle illustration without a redundant Vehicle Profile label.

The vehicle-list overflow menu should include a Settings destination where the user can read setup instructions and paste their own OpenAI API key. When a saved key is needed for document extraction or display, Orca should prompt for biometrics or device credentials at that point instead of requiring a separate manual unlock step in Settings first.

Vehicle detail should expose a visible Import Document floating action button on that screen, using a different blue treatment than the home-screen FAB so document import stays easy to find without competing with the vehicle-profile card layout.

When at least one vehicle already exists, the vehicle-list floating action button should open an anchored menu just above the FAB with both Create Vehicle and Import Document for an existing vehicle.

Before opening the system picker for document import, Orca should show a short guidance dialog that explains the user can select multiple images or PDF files and that the app will process them. The dialog should keep appearing until the user explicitly checks Don't show again.

Vehicle detail should show a maintenance summary table below the vehicle profile and above the document list. Each row should summarize one recent maintenance or repair item for that vehicle, with the first column showing the related vehicle component or system and the second column showing the maintenance or repair performed.

Vehicle detail document cards should expose a manual retry action when extraction has not started yet or has failed, so the user can resubmit that document to cloud AI without re-importing the source files.

Example rows may include brake system | brake fluid replaced, engine | engine air filter replaced, or wheel | tire rotation performed. The table should favor the most recent known work for each component so the user can quickly understand what was maintained and when.

Document Processing

For each imported maintenance document, try to extract the service date, mileage, vendor or service provider, service items, parts or fluids, total cost, and provider notes or recommendations.

Each extracted field should link back to the source document.

Document detail should use a stable top app bar title of Document details. The summary card should use the same visual treatment as the vehicle profile card, show a concise source-file size summary, disclose that original PDFs and images are sent to cloud AI during extraction, and avoid redundant helper copy such as thumbnail tap instructions.

When extraction is queued, running, retried, or failed, document detail should explain the state in plain language, including network or provider-delay cases and the fact that large PDFs or multi-file imports may take longer.

When a receipt uses dealer shorthand, abbreviations, or maintenance package codes, preserve the raw text and optionally show an AI-generated plain-language interpretation with confidence and citation.

Maintenance Timeline

  • Date
  • Mileage, if available
  • Vendor, if available
  • Summary of service performed
  • Cost, if available
  • Link to source document
  • Unverified state until user confirmation or correction

Search, Questions, and Corrections

Answers should include

  • Concise answer
  • Source citations
  • Relevant dates and mileage
  • Uncertainty note when records are incomplete or ambiguous

V1 may limit supported questions to maintenance-history lookups such as the last recorded service overall or the latest known work for a recognized component, as long as unsupported prompts are handled explicitly rather than guessed.

User correction

  • Document subtype
  • Service date
  • Mileage
  • Vendor
  • Service items
  • Cost

Corrected facts and edited service items should be treated as user-verified data. When a service item is edited, only that specific item should show a verified badge in document detail.

AI interpretations of shorthand should remain unverified until the user confirms or replaces them.

Answer quality requirements

  • Cite source documents for factual answers.
  • Distinguish document facts from inferred conclusions.
  • Say when records do not support an answer.
  • Show conflicting records when documents disagree.
  • Prefer narrow supported answers over broad unsupported ones.
  • Distinguish raw dealer text from AI-expanded interpretations in the UI and in answers.

Success Metrics

  • Users who create at least one vehicle profile
  • Documents imported per vehicle
  • Maintenance fact extraction success rate
  • Timeline views per active user
  • Questions asked per active user
  • Percentage of answers with citations
  • User correction rate for extracted fields
  • User-reported answer helpfulness

Risks

  • Document formats vary widely.
  • Cloud AI may raise privacy concerns.
  • Cloud AI cost and latency may affect import experience.
  • Extraction may still be wrong and require user review.
  • Some users may wait for privacy mode before adopting.

Open Questions

  • What privacy guarantees and user disclosures are required for cloud AI processing?
  • When should local-model privacy mode be introduced?
  • Should manufacturer maintenance intervals stay out of scope until extraction is more reliable?
  • Which non-maintenance vehicle documents should be prioritized after V1?
  • How much brand-specific interpretation should V1 allow before it crosses from grounded explanation into unsupported maintenance advice?
